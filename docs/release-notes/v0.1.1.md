# v0.1.1

A packaging-only release: one label, changed in one file. No controller, CRD,
RBAC, webhook or image change, and no migration steps from v0.1.0.

These notes were written retrospectively. v0.1.1 was tagged and released on
2026-08-10 without a changelog entry or release notes; this file closes that
gap.

## Changed

- **The clusterctl provider identity is now `kairos-io-fleet`.** The
  `cluster.x-k8s.io/provider` label that clusterctl stamps onto every object
  this provider owns changed from `infrastructure-kairos-fleet` to
  `infrastructure-kairos-io-fleet`, in preparation for registering the provider
  in the upstream clusterctl built-in provider list under the `kairos-io`
  organisation name. This mirrors the same change made in the sibling
  [Kairos bootstrap and control-plane providers](https://github.com/kairos-io/cluster-api-provider-kairos)
  at their v0.1.1.

  The label is applied with `includeSelectors: false`, so Deployment and
  Service selectors are untouched and the components stay self-consistent.

## Upgrade notes

From v0.1.0 there are no migration steps. Re-running `clusterctl init`, or a
`clusterctl upgrade`, restamps the label on the provider's objects.

One thing to be aware of: `cluster.x-k8s.io/provider` is the label
`clusterctl move` and `clusterctl delete` use to find a provider's objects. A
management cluster initialised under v0.1.0 carries the old
`infrastructure-kairos-fleet` value until it is upgraded, so upgrade before
relying on either command.

## Versions

Unchanged from v0.1.0: Cluster API v1.13.4 (v1beta2 contract), management
Kubernetes v1.32 to v1.36, Kairos v4.1.2. See the
[v0.1.0 release notes](v0.1.0.md).
